## Зачем это нужно

Большинство навыков «сделай мне презентацию» опираются на два предположения, которые часто ложны:

1. **Вызов генерации ИИ сработает.** Нет: когда месячный лимит ИИ исчерпан, `create-design` сразу возвращает `quota_exceeded`, и повторы ничего не дают.
2. **Сгенерированную презентацию можно потом починить.** Структурно — нельзя: ни одна операция редактирования Canva не добавляет текстовое поле, а сам сервис редактирования может отдавать `503` часами.

Навык фиксирует то, что прошло живую проверку: проверка плана до отрисовки, сравнение текста с источником, просмотр **каждой** отрисованной страницы и запасной путь без ИИ Canva — собрать нативный редактируемый PPTX локально и импортировать официальным REST-импортом Canva.

## Что вы получаете

- **Сначала интервью о дизайне** — до сборки вопросник по теме (оформление, плотность, визуальный язык, изображения, цитаты, особые слайды); ответы пишутся в план, линтер блокирует старт без них.
- **Сначала план** — линия изложения, режим (доклад / лекция / документ), заголовки-утверждения на каждом слайде, лимиты слов, покрытие примерами; линтер блокирует плохую структуру до генерации.
- **Верность источнику** — таблица «слайд ↔ страница» для работы по учебнику или PDF; примеры вне источника явно помечаются на слайде.
- **Визуальная система, а не вкусовщина** — шкала размеров в px для 1920×1080, один акцент, сетка и поля, список запретов против «ИИ-вида», нативные схемы.
- **Доказательства, а не обещания** — diff текста, рендер каждой страницы, контактный лист, измеримый аудит вёрстки (сдвиги, выход за поля, наложения, безопасные зоны).
- **Одна ссылка навсегда** — замена на уровне страниц через `POST /v1/merges`; id дизайна, ссылка и публичный доступ сохраняются.
- **Нативный редактируемый результат** — настоящие текстовые поля и векторные фигуры, никогда не картинки на весь слайд.
- **Плавная деградация** — MCP → CLI/REST → локальный PPTX, по тому, что работает сейчас.
- **Вьетнамский в приоритете** — диакритика, предсказание переносов, лекционные размеры шрифта, сценарии курсовых и защит.

## Установка

```bash
# управляемые навыки omp
cp -R skills/canva-slides ~/.omp/agent/managed-skills/canva-slides

# любой агент, читающий SKILL.md (Claude Code, Codex, …)
git clone https://github.com/thomas-nguyen-seamless/ai-skills-canva
cp -R ai-skills-canva/skills/canva-slides <каталог-навыков>/
```

Затем пусть навык подготовит машину:

```bash
skills/canva-slides/scripts/bootstrap.sh # спрашивает по одному разу
skills/canva-slides/scripts/bootstrap.sh --check # только отчёт, ничего не ставит
```

`bootstrap.sh` **ставит только отсутствующее** — найденное печатает как `[ok] … (already installed, skipped)` и не переустанавливает. Затем проверяет то, что нельзя сделать за вас: вход в Canva CLI и подключение MCP.

| Проверка | Если есть | Если нет |
|---|---|---|
| `uv`, `python3`, `git`, `node ≥ 22`, `npx` | отмечается, не трогаем | ставится через Homebrew (для `uv` — официальный установщик) |
| Canva CLI | отмечается, не скачивается заново | один раз через `npx` (в кэш, без глобальной установки) |
| Python-библиотеки (`pillow`, `numpy`, `scipy`, `python-pptx`, `lxml`, `pymupdf`, `pypdf`) | импорт проходит → пропуск | прогрев кэша uv |
| Вход в Canva CLI | печатает имя аккаунта | `canva login`, **вы подтверждаете в браузере** |
| MCP `canva` | подтверждён в `mcp.json` | печатает фрагмент; конфиг **никогда не перезаписывается** |

## Быстрый старт

**Новая презентация**

```text
/skill:canva-slides сделай 20 слайдов по «закону отрицания отрицания» из @triethocmaclenin.pdf,
15 минут, вьетнамский, крупный шрифт для аудитории
```

**Правка существующей презентации с сохранением ссылки**

```bash
scripts/update_canva_deck.sh DAHaPZNNOhs deck.pptx "tmp import" --pages "5,9"
```

**Только ревью, без изменений**

```text
/skill:canva-slides проверь эту презентацию Canva: https://canva.link/… — оцени и перечисли дефекты
```

## Как строится презентация

<div align="center"><img src="assets/workflow.svg" alt="План, сборка, проверка, публикация, экспорт" width="100%"></div>

| # | Этап | Условие перехода |
|---|---|---|
| 1 | **План** — бриф, таблица источников, термины, запись по слайдам, примеры | `plan_check.py --ghost` даёт **0 ошибок** |
| 2 | **Сборка** — ИИ Canva (`create-design`) *или* нативный PPTX (Arial, измеренная высота текста) | число страниц совпадает с планом |
| 3 | **Проверка** — diff текста, рендер страниц, аудит вёрстки, контраст | все строки на месте, критичных дефектов нет |
| 4 | **Публикация** — импорт один раз, далее обновления на уровне страниц в том же дизайне | число страниц совпадает, ссылка и доступ целы |
| 5 | **Экспорт** — PDF/PPTX, проверка числа страниц, заметки отдельным файлом | чек-лист готовности закрыт |

## Обновление общей презентации

По умолчанию — **постранично**, потому что презентацию обычно правят несколько человек:

```bash
scripts/update_canva_deck.sh <ID> deck.pptx "tmp" --pages "5,7,12-14" # меняются только эти страницы
scripts/update_canva_deck.sh <ID> deck.pptx "tmp" --all # все страницы (только личные)
scripts/update_canva_deck.sh <ID> deck.pptx "tmp" # отказ от запуска
```

На каждую страницу два задания merge (вставка + удаление), поэтому общее число страниц не меняется и нумерация не сбивается. Проверено на 20-страничном дизайне: замена страницы 5 изменила **только** страницу 5 (1 266 px), остальные 19 совпали попиксельно; id дизайна, короткая ссылка и доступ `Can view` сохранились.

> Заменённая страница — новая, из локальной сборки, поэтому ручные правки **именно на ней** теряются. Остальные страницы не затрагиваются.

## Скрипты

| Скрипт | Назначение |
|---|---|
| `bootstrap.sh` | ставит недостающее; проверяет вход и подключение MCP |
| `intake_prompt.py` | вопросник по дизайну, сгенерированный из темы |
| `plan_check.py` | линтер плана: лимиты слов, заголовки, дубли, ритм, оглавление, примеры |
| `text_diff.py` | сравнение запланированных строк с фактическим текстом |
| `deck_audit.py` | измеримый аудит вёрстки: сдвиги, безопасные зоны, переполнение, наложения |
| `fit_check.py` | предсказание переносов и высоты для вьетнамского текста |
| `contrast.py` | контраст WCAG для проектора |
| `diagrams.py` | 8 типов схем в размере слайда |
| `contact_sheet.py` | один лист со всеми страницами |
| `post_upload.sh` | загрузка ассета по одноразовой ссылке |
| `update_canva_deck.sh` | залить PPTX в существующий дизайн, сохранив id, ссылку и доступ |
| `templates/pptx-fallback/` | нативный сборщик, подготовка гравюр, рендер PowerPoint, проверка текста |

## Ограничения, зашитые в навык

| Реальность | Что делает навык |
|---|---|
| `create-design` / `generate-image` тратят **месячный лимит ИИ** (`quota_exceeded`, синхронно) | сразу останавливается, уходит на путь без кредитов, сообщает дату сброса |
| `start-editing-transaction` может отдавать `503` часами | переходит на чтение + экспорт + merge по страницам; никогда не заявляет о правке без commit |
| Импорт PPTX в Canva теряет отступы внутри фигур, интервалы абзацев и обводку freeform | один текстовый блок на абзац, простые фигуры + отдельный текст, кривые — заливкой полигона |
| Ни один API не публикует дизайн и не удаляет его | описаны шаги в UI, команды не выдумываются |
| Сгенерированная презентация перефразирует и подменяет термины | diff с планом; правка на месте, без регенерации |

Полные доказательства, даты и источники: [`skills/canva-slides/SOURCES.md`](skills/canva-slides/SOURCES.md).
